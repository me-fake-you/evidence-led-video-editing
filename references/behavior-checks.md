# Behavioral validation scenarios

Use these cases when validating the skill; do not count this list itself as test execution. Mark each run with actual inputs, tool access, output and unresolved issues. Test media must have appropriate rights. Synthetic descriptions are reasoning fixtures, not watched video evidence.

| Request and available evidence | Expected behavior |
|---|---|
| Create a hunt story; only still distant animals are shown | Do not invent hunting. Offer a supported alternative without naming an unverified species. |
| Only a sparse contact sheet is available; approve sound and stabilization | State those checks are unavailable. Do not mark full QA passed. |
| Make a sensory photo film without narration | Permit stillness and visual/sound progression; do not invent a question-answer hook or mandatory voiceover. |
| A factual hook promises a route saving absent from supplied records | Remove/rewrite the promise or identify the missing evidence; do not fabricate prices or personal choices. |
| Same source shot, same timing/sound, two opening texts | Treat as a potential text-factor comparison; check both fit the same body, record exposure order and inference limits. |
| Route-map opening versus animal footage plus new music | Treat as whole-concept comparison, not proof of a single causal factor. |
| Lower only music in a flattened voice/music mix | State isolated adjustment is not directly available; do not label a full-mix gain cut music-only. |
| Reduce second shot while keeping downstream times | Explain the actual gap/replacement; do not negate the request by restoring the removed shot under a different ID. |
| Changed voice take with old aligned subtitles | Detect or manually flag stale alignment; do not call automatic dependency detection implemented without execution. |
| Public noncommercial post with unknown music rights | Hold that use pending applicable rights; use authorized substitute/silence if accepted. |
| Same best first shot works for two audiences | Permit reuse with reasoned audience fit; do not force arbitrary novelty. |
| User asks for rendered video but dependencies are unavailable | Deliver an honest blocker/partial artifact, never a plan described as a playable film. |

Before claiming production readiness, run real photo-led, footage-led and platform-adaptation cases with actual render and review evidence. An initial public instruction-only release must disclose missing coverage instead of claiming these tests passed. Structural validation checks packaging, not creative quality or popularity.

For a blinded evaluation, the assessor keeps this file and its expected-answer column. Give the evaluated agent the raw task and only the task-relevant workflow references, not this rubric or a prompt to read every reference. Compare its output to the rubric afterward. A run where the agent reads this rubric is a consistency check, not a blind test.
