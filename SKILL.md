# Evidence-led video editing

This skill guides editing decisions. It does not install a renderer, provide an InVideo integration, or grant publishing authority. Use the user's existing editor and available local tools; detect missing capabilities instead of inventing tools or claiming a render occurred.

## Start from the actual task

Read project instructions and the latest approved brief. Identify the authorized source subset, current revision, intended audience/platform, duration, language, sound preferences and requested deliverable. Preserve source files, previous outputs, user edits and schedules. Do not scan the full library just because a source folder exists.

Choose the relevant workflow; read only the references needed:

- New story, source selection or narration: [source-and-story.md](references/source-and-story.md).
- Opening, pacing or performance diagnosis: [hooks-and-retention.md](references/hooks-and-retention.md).
- Photo correction, video grading, stabilization, narration, music or subtitles: [picture-and-sound.md](references/picture-and-sound.md).
- Scoped changes, versions, rendering or platform editions: [revisions-and-delivery.md](references/revisions-and-delivery.md).
- When assessing validation results or extending this skill: [behavior-checks.md](references/behavior-checks.md). This reference contains expected answers; keep it assessor-only during a blinded evaluation.

For a small change, preserve the approved story and fix only what is requested. For a substantial edit, first connect real source ranges to a story and sound plan, then render a bounded preview if it resolves a meaningful uncertainty. Do not substitute endless planning or repeated previews for the requested full deliverable.

## Invariants

- Separate visible observations, inferred interpretations, verified claims and editorial choices. A model confidence score does not establish a location, personal experience or animal behavior.
- Inspect selected photos and save individually justified, non-destructive full-resolution corrections before using them. Preserve real geography, objects, weather and intended depth of field; do not manufacture replacement travel evidence. Review video corrections per shot.
- Preserve creative preferences. Do not force a fixed opening formula, runtime, cut frequency, narration ratio, font color, music language or soundtrack type.
- Keep director notes separate from audience copy. Practical travel content needs supported practical information, not an explanation of shot sizes.
- Distinguish proposed, implemented, rendered, technically checked, motion-reviewed, listened, user-approved and published. Unknown or unavailable checks remain unknown.
- Music rights, private-media upload permission, installation and publishing are separate decisions. Unknown applicable rights block public use, whether or not monetized. Do not infer commercial-activity eligibility from a download or user attestation alone.
- Publishing is outside the core editing workflow. Preserve the project's account isolation, exact-revision approval, duplicate checks and schedule policy. Use only an available authorized publishing workflow, and verify remote state.

## Smallest useful handoff

Return the actual preview/final artifact when produced, its exact revision, a concise list of changes, and unresolved viewing/listening/rights gaps. Keep rebuild information alongside the output: source ranges and hashes, edit and sound decisions, actual voice takes, renderer settings, review results and final artifact hash as appropriate. Do not require a database or eight separate JSON files for a small manual edit.

Never claim this workflow guarantees popularity or reconstructs a commercial product's private implementation. Prices, API limits, metric definitions and product capabilities must be checked against current primary sources when used, not copied from an old conversation.
